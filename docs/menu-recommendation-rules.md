# メニュー提案ルール

この文書は、2026年9月10日の会話を実装へ落とし込んだ設計仕様です。
種目別の総挙上重量を維持し、回数・重量の段階的な増加を支援します。
個人の最適なトレーニング量や筋肥大量を予測するものではありません。

## 実装範囲

- `lib/workout-rules.ts`: 8種目の回数帯、基本セット数、器具の重量段階。
- `lib/workout-recommendations.ts`: 既存形式の記録からメニュー候補、理由、確認事項、期間集計を返す純粋関数。
- `components/RecommendationPanel.tsx`: 次回メニューと直近7日・28日週平均を表示。
- `app/page.tsx`: 記録入力、生データ編集、次回メニューを接続。
- `supabase/migrations/20260910_add_affects_recommendation.sql`: 軽い日の判定列を追加。
- `npm run test:rules` で判定ロジックを検証できます。

## 基本ルール

| 種目 | 回数 | セット | 休憩の目安 |
|---|---|---|---|
| ダンベルチェストプレス | 8–12 | 3 | 180秒 |
| ダンベルショルダープレス | 8–12 | 3 | 180秒 |
| インクラインサイドレイズ(左右) | 12–20／側 | 3／側 | 120秒 |
| 懸垂 | 6–10 | 3 | 180秒 |
| ワンハンドローイング(左右) | 8–12／側 | 3／側 | 180秒 |
| ダンベルデッドリフト | 6–8 | 2 | 180秒、必要なら延長 |
| ブルガリアンスクワット(左右) | 8–12／脚 | 2／脚 | 180秒 |
| アブローラー(膝コロ) | 8–15 | 2 | 120秒 |

通常記録は、利用者の運用に合わせて限界近くまで行った実績として扱います。回数はそこで止める指示ではなく、増量判断の範囲です。
同じ重量を基本セット数以上行い、全セットが上限回数に2回連続で到達したら増量を提案します。
実際に予定より回数・セット数を増やした場合や、軽い重量へ落とさず重いまま続けた場合も、その実績を受け入れます。ただし次回の予定セット数は自動で増やしません。
フォーム不良、左右差、息切れ・握力・痛みなどが明示された場合は増量を見送ります。1日に複数回行っても、既存データにはセッションIDがないため1回と数えます。

## 器具と移行

ダンベルは片手あたり `10x - 5, 10x - 2.5, 10x` lb、整数 `x = 2..8`。
15, 17.5, 20, 25, …, 75, 77.5, 80lbとなります。
過去の10lb等はこの式に含まれないため、現在使えるかを確認し、呼び出し時の重量一覧で上書きします。
架空の22.5lbや器具上限を超える重量は提案しません。

増量率が10%を超える場合、新重量1セット＋元の重量の残りセットへ移行します。
新重量と元の重量で下限回数を満たしたら、元の重量の1セットを新重量に置き換えます。
10%は段階的な移行を選ぶための製品上の仮設定で、安全性や筋肥大を保証する境界ではありません。
候補重量で下限回数やフォームを保てなければ増量を見送ります。予定より調子がよく、全セットを新重量のまま行った実績も有効です。

懸垂の加重器具はダンベルと独立した重量一覧（自重の0lbを含む）を指定します。
増量率には現在の体重＋追加重量を用います。体重を60kgと仮定する処理はありません。
アブローラーは上限達成後に難度の確認を返し、自動で加重・立ちコロへ進めません。

## 通常記録・軽い日・中断

入力時の「今日は軽く動くだけ」を選んだ記録には `affects_recommendation = false` を保存します。
専用列がまだないデータベースでは、同じ意味を持つ `[[light-session]]` をコメント先頭へ保存し、画面上では非表示にします。列の追加後は自動で専用列を使います。
この記録も実施回数、セット、回数、週間総量へ含めますが、重量・回数・セット配分の提案更新には使いません。
軽い日が通常記録の後にあっても、その前の通常記録から作ったメニューを維持します。
ただし最後の通常記録から14日以上空けば、途中に軽い日があっても `reassess` を返します。
既存行と列がない時代の行は通常記録として扱います。

前回から14日以上空いた場合は `reassess` と過去の参考メニューを返し、現在の重量を自動決定しません。
14日は変更可能な運用上の仮設定で、筋肉が減る日数を示すものではありません。
当日の疲労・痛みが入力されていれば、増量とセット追加を保留します。
記録日が古いことは「実際に運動していない」と断定せず、記録の確認を促す意味です。

## 総挙上重量・期間集計

- 基準日を含む直近7日、直前の7日、直近28日を計算。
- 28日総量÷4で、未実施日も含めた週平均を表示。
- 未来の記録・明示されたウォームアップは除外。軽い日は含める。
- 現行アプリの数え方を継承：ダンベル通常は負荷×回数×セット×2、ブルガリアンスクワットは×4。
- 懸垂は（体重kg×2.20462＋追加重量lb）×回数×セット。
- 膝コロは体重lb×0.6×回数×セット。ただし `bodyweight-proxy` と明示する既存の推定指標で、実測重量ではありません。
- 体重が不明なら該当総量は `null` とし、0として集計しません。
- 予定総量は回数帯の最小値・最大値で表示。RIRを反映した筋肥大スコアにはしません。
- 前回より総量が下がっても自動的にセット数を増やしません。

左右別の回数は片側の回数、セット数も片側のセット数として扱います。
ダンベル重量は片手分という既存の計算前提をUI接続時に確認してください。

軽めのセットの「追加」は自動化せず、まず予定セット内の配分変更を実装しています。
予定セット数は `workingSets` で変更できます。実績のセット数が多くても、次回の予定セット数は勝手に増やしません。
週間総量不足だけを理由に増量・セット追加はしません。週間の頻度配置や長期のセット数調整は次の設計範囲です。

## 呼び出し例

```ts
const proposal = recommendWorkout('ダンベルチェストプレス', rawRecords, {
  asOf: '2026-09-10',
  readiness: 'ready',
});
```

`asOf` には利用者のローカル日付を渡してください。
`recommendationMode`, `formConfirmed`, `bothSidesConfirmed`, `warmup`, `stoppedBy` は判定用の任意項目です。
UIでは `affects_recommendation = false` を `recommendationMode = 'light'` に変換します。

## 根拠と設定の区別

回数と重量の双方で漸進させること、広い負荷帯で筋肥大が起こること、努力度や週間量を考慮することは研究に基づきます。
各種目の厳密な回数上限、2回連続の確認、14日の再確認基準、10%の移行基準は、研究から一意に求まった最適値ではありません。

- ACSM 2026: https://pubmed.ncbi.nlm.nih.gov/41843416/
- 重量増加と回数増加の比較: https://pubmed.ncbi.nlm.nih.gov/36199287/
- 負荷・回数帯: https://pubmed.ncbi.nlm.nih.gov/33671664/
- RIRと筋肥大: https://pubmed.ncbi.nlm.nih.gov/38970765/
- 週間量と頻度: https://link.springer.com/article/10.1007/s40279-025-02344-w
ストレッチや呼吸の仕方など、ここに含まれない技術指導は自動判定しません。
